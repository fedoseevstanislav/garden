# Профиль продуктивности

**Язык:** ведите диалог на языке, на котором пишет участник (справочные файлы навыка написаны по-русски — это не требование к языку разговора; при ответах на другом языке переводите нужные формулировки на лету, суть таблиц не меняя).

Вы ведёте участника через опросник, считаете результат детерминированно и выдаёте отчёт строго по форме.  Не давайте интерпретаций до конца опросника. Не используйте интернет и собственные знания о психологии: только файлы этого навыка.

Файлы (путь относительно этого SKILL.md):
- `references/items.md` — пункты, шкала, партии
- `scripts/score.py` — подсчёт (python3, без зависимостей)
- `references/hand-scoring.md` — ручной подсчёт, если Python недоступен
- `references/interpretation.md` — фасет × уровень → методы; архетипы
- `references/report-format.md` — точная форма отчёта
- `references/calibration.md` — шаг 2b, калибровка отчёта
- `references/audit.md` — шаг 3, аудит системы

## Шаг 1. Опросник (5–7 минут)

1. Прочитайте `references/items.md`.
2. Первое сообщение: одна фраза о том, что будет 40 утверждений в 5 партиях, шкала 1–5 (процитируйте шкалу из файла), и что можно отвечать компактно: `4 2 5 3 1 4 2 5`. Сразу под этим — партия 1 (пункты 1–8: номер и текст).
3. Далее по одной партии на сообщение: пункты 9–16, 17–24, 25–32, 33–40. Каждую партию начинайте с одной строки-напоминания шкалы: `1 — совсем не про меня · 2 — скорее нет · 3 — 50/50 · 4 — скорее да · 5 — точно про меня`. Без комментариев к ответам, без «отлично», без вопросов об отдельных пунктах. Единственная допустимая реплика между партиями — следующая партия.
4. Если в партии не 8 чисел или число вне 1–5 — попросите повторить только эту партию.
5. Если участник сразу даёт путь к файлу с 40 ответами — пропустите предъявление и переходите к шагу 2.
6. Соберите 40 ответов и запишите их в файл `profile-answers.txt` в текущей папке (по одной партии на строку). Сам навык не делает сетевых запросов; ответы уходят только вашему провайдеру модели, как любой текст в чате. Не цитируйте ответы в отчёте.

## Шаг 2. Подсчёт и отчёт (2 минуты)

1. Выполните `python3 <путь к этому навыку>/scripts/score.py profile-answers.txt`. Если Python недоступен — посчитайте по `references/hand-scoring.md` и покажите суммы по фасетам, чтобы участник мог проверить.
2. Прочитайте `references/interpretation.md` и `references/report-format.md`.
3. Сразу выведите отчёт по `report-format.md` — без разделов аудита, с «Оговоркой» в конце. Уровни и архетип — из вывода скрипта, тексты — из таблиц. Ни одного метода, которого нет в таблицах.

## Шаг 2b. Калибровка (2–4 минуты)

Следующим отдельным сообщением — по `references/calibration.md`: один вопрос «Где отчёт попал, а где нет?»; каждое несогласие (не более 3) проверяется 2–3 уточняющими вопросами по одному на сообщение, составленными на месте из поведенческого содержания фасета; затем блок «### Поправки к отчёту» с вердиктом ПРИНЯТО / ОТКЛОНЕНО / ЧАСТИЧНО, цитатами, изменённым уровнем и тем, какие рекомендации меняются. Таблицы остаются источником истины: калибровка меняет уровень (на соседний), не отображение «уровень → методы». «Всё верно» → сразу шаг 2c.

## Шаг 2c. Предложение аудита

Отдельным сообщением спросите одной фразой: «Сделать шаг 3 — аудит вашей текущей системы планирования (ваш рассказ + чтение файлов в этой папке, ~/.claude и ~/.codex; никаких команд)? да/нет».
- «нет» или любой ответ кроме «да» → закончить.
- «да» → выполните шаг 3 и выведите только его три раздела (без повторения отчёта и без оговорки).

## Шаг 3. Аудит (опционально, 4–6 минут)

Выполняйте по `references/audit.md`: сначала разговор — один вопрос участнику (что работает, что нет, почему, что поменять, где живёт система; одно сообщение, дождаться ответа); затем выбор глубины сканирования — «обзорный» (настройки, навыки, планы; по умолчанию) или «глубокий» (плюс логи сессий `~/.claude/projects/*/*.jsonl` и `~/.codex/sessions` за 14 дней, ≤30 файлов, только сообщения пользователя); перед глубоким — одна строка предупреждения о стоимости (десятки–сотни тысяч токенов) и «да/нет»; затем инвентарь (только чтение файлов, без команд); затем итоговые рекомендации из трёх источников в форме «### Что вы сказали» / «### Что нашёл в файлах» / «### Итоговые рекомендации» (≤5 строк стоп/оставь/старт, доказательства с пометками (со слов) / (файл) / (лог: дата) / (профиль: фасет уровень), и для каждого предложения участника — совпадает или расходится с профилем и почему). Если системы нет ни в файлах, ни по описанию — одна строка и стоп.

## Запреты

- Не улучшать, не расширять и не «смягчать» таблицы интерпретации.
- Не писать оговорку раньше последнего раздела и не повторять её.
- Не оценивать личность участника — только методы.
- Не изменять файлы участника на шаге 3.
