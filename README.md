# garden — четыре навыка для семинара S26: профиль, мини-ТЗ, петля проверки, игра

Плагин для Claude Code и Codex CLI с четырьмя навыками:

- **`mini-tz`** — интервью на одну задачу (текст, презентация, скрипт, автоматизация): зачем · для чего · что именно · чего не надо → файл `мини-тз.md`; критерии приёмки в форме да/нет агент выводит сам из ваших слов, вы только поправляете.
- **`profile`** — 40 утверждений → профиль продуктивности → какие методы планирования вам подойдут, а какие провалятся. Опционально агент читает вашу текущую систему (CLAUDE.md, планы, брифы, трекеры) и говорит, что остановить, оставить и начать.
- **`play`** — интервью на 10 минут: что для вас игра — состояние, в котором работа ощущается как игра, — что её убивает и сколько её в вашей неделе → файл `игра.md` с тремя вопросами с собой.
- **`review-loop`** — «проверил другой моделью → исправил → проверил снова»: результат уходит модели другого семейства, чинится только то, что не прошло. Работает по критериям из `мини-тз.md` и без них — тогда проверяющий сверяет результат с исходной просьбой. Тем же навыком проверяют и сам `мини-тз.md`.

Автор: Стас Федосеев. Упражнение для лаборатории AI Mindset S26. Лицензия MIT.

**Бюджет времени:** profile 10–15 мин (опросник 5–7, отчёт 2, аудит 3–5) · play ~10 мин · mini-tz 10–15 мин · review-loop — зависит от проверяемой работы.
**Модель:** используйте лучшую модель, которая у вас есть, — форма отчёта строгая, слабые модели её ломают.
**Оговорка про установку:** плагины и навыки — молодые механизмы, на вашей версии инструмента может не завестись. На этот случай ниже есть вариант «вставить промпт».

## Claude Code — 3 шага

```bash
claude plugin marketplace add fedoseevstanislav/garden
claude plugin install garden@garden
claude
```

В сессии наберите `/garden:profile` и отвечайте на партии вида `4 2 5 3 1 4 2 5`. Остальные навыки — `/garden:mini-tz`, `/garden:review-loop` и `/garden:play`.

Те же команды работают внутри сессии как `/plugin marketplace add ...` и `/plugin install ...`.

## Codex CLI — 3 шага

```bash
git clone https://github.com/fedoseevstanislav/garden
mkdir -p ~/.codex/skills && cp -r garden/skills/* ~/.codex/skills/
codex
```

В сессии напишите: «Пройди со мной навык profile». Если Codex не подхватил навык — запустите `codex` прямо из папки `garden` (там лежит `AGENTS.md` с указателем) или используйте вариант ниже.

## Если ничего не установилось — вставьте промпт

Скачайте или клонируйте репозиторий, запустите любой агент из его папки и вставьте:

```
Прочитай skills/profile/SKILL.md и выполни его по шагам, начиная с партии 1 опросника. Язык — русский. Интерпретации только из файлов references/, подсчёт через scripts/score.py.
```

Для навыка `play` промпт такой:

```
Прочитай skills/play/SKILL.md и выполни его по шагам: интро, интервью по одному вопросу за раз, read-back, файл игра.md. Язык — русский.
```

## Цикл: /mini-tz → работа → /review-loop

Автор не видит дыр в собственной работе — он видит свой замысел. Поэтому проверяет другая модель, а не вы и не та же самая модель.

1. `/garden:mini-tz` — интервью на 10–15 минут: вы отвечаете живой речью, агент сам переводит её в критерии `C1…Cn` (каждый с ответом да/нет) и запреты `A1…An`, помечает ⚠️ то, что вывел с натяжкой, и после вашего «всё так» пишет `мини-тз.md`. Хотите проверить само ТЗ — `/garden:review-loop мини-тз.md` до работы: другая модель сверит файл с вашими словами и назовёт вопрос, который не был задан.
2. Делаете работу — сами или с агентом. Мини-ТЗ и есть задание.
3. `/garden:review-loop` — другая модель читает результат и выносит вердикт: по `C` и `A`, если мини-ТЗ есть, иначе по исходной просьбе (сделано ли то, что просили, ничего ли не выдумано, нет ли лишнего). Агент чинит только `НЕ ПРОШЁЛ`; по умолчанию три раунда, молчаливой приёмки нет.

Проверяющий — всегда другая модель: из Claude Code — `codex exec` только на чтение, из Codex — `claude -p`, иначе подзадача с явно другой моделью. Другой модели нет — агент скажет об этом и остановится.

## /play — найти свою игру

«Я продуктивен, когда я счастлив, а я счастлив, когда я играю» — инверсия привычного: не продуктивность ради счастья, а игра как источник продуктивности. Якорь — вопрос Naval Ravikant: «What feels like play to you, but looks like work to others?»

`/garden:play` — интервью по одному вопросу за раз: что со стороны похоже на работу, а изнутри — игра; что вы делали бы, даже если бы никто не видел и не платил; последний раз, когда вы «пропали» в деле; что превращает игру в не-игру; сколько её в неделе. На выходе `игра.md`: формулировки вашей игры вашими же словами, что её убивает, сколько её сейчас — и три вопроса с собой: «Как добавить игры?» · «Что могут сделать агенты, чтобы игры стало больше?» · «Как перестроить систему продуктивности под игру?»

## Что делать с результатом

1. Посмотрите на раздел «Не подходит». Если там то, чем вы пользуетесь последние месяцы и что «не держится», — вы нашли причину.
2. Возьмите одну строку «старт» из аудита (или одну из «Подходит») и попробуйте её две недели. Не перестраивайте всё.
3. Сравните с соседом по лаборатории: один и тот же метод у разных архетипов даёт разный результат.

## Что внутри

- `skills/profile/SKILL.md` — процедура для агента
- `references/items.md` — 40 пунктов IPIP-NEO (общественное достояние), русский перевод не валидирован
- `scripts/score.py` — детерминированный подсчёт, `python3 score.py answers.txt`
- `references/hand-scoring.md` — ручной подсчёт без Python
- `references/interpretation.md` — фиксированная таблица фасет × уровень → методы, 6 архетипов
- `references/report-format.md`, `references/audit.md` — форма отчёта и аудита
- `skills/mini-tz/SKILL.md` — интервью на требования, форма `мини-тз.md`
- `skills/play/SKILL.md` — интервью про игру, файл `игра.md`
- `skills/review-loop/SKILL.md` — цикл проверки; запрос проверяющему внутри
- `tests/` — два синтетических набора ответов и проверка согласованности ключей

Фасеты: Порядок, Самодисциплина, Стремление к результату, Обязательность, Обдуманность (добросовестность), Темп (экстраверсия), Стресс-реактивность (нейротизм), Потребность в новизне (открытость). Уровни по сумме 5 пунктов: low 5–12, mid 13–17, high 18–25.

Приватность: плагин не делает собственных сетевых запросов; ваши ответы уходят выбранному вами провайдеру модели, как любой текст в чате. Отдельно про `review-loop`: он передаёт мини-ТЗ и проверяемый результат **второму** провайдеру — тому, чью модель вы выбрали проверяющим. Не направляйте его на файлы с секретами и чужими данными. Результат и ответы сохраняются локально в `profile-answers.txt` в текущей папке — удалите, если не нужны. Аудит — только чтение файлов, без команд.
